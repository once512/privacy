# 维护流程与当前待办

公开 HTML 保留根目录和现有文件名，避免应用内及 Google Play 后台填写的 URL 失效。应用源码只读采集；核查记录和历史文件放入 docs。

## 采集与更新

1. 记录仓库、分支、完整提交、工作区状态、版本和系统要求。有未提交改动时说明是否纳入核查，不用提交号冒充完整工作区快照。
2. 对照 README、Manifest、Gradle、文件／密码／音频处理、偏好、临时文件、删除／导出／备份、SDK、同意、奖励及购买实现。区分源清单权限和实际构建合并权限。
3. 不采集 `.env`、密码、令牌、签名私钥、服务账号凭证或用户真实文件；不为文档核查运行真实广告、支付、删除、录音或清除应用数据。
4. 将事实、源码依据、待确认运营信息分别记录于 reviews。不能将计划功能、旧说明或测试包结果写成已上线事实。
5. 更新对应隐私政策，并检查公共条款和该应用中英文专属章节；各应用奖励、缓存和删除机制按各自实现维护。
6. 内容实际变化才更新政策日期。只移动核查资料不改法律页面日期；本次三款隐私政策及公共条款均有内容更新，日期统一为 2026-11-10。

## 检查与发布

运行 `node scripts/validate.mjs` 和 `git diff --check`；阅读中英文差异。结构校验不含浏览器视觉检查、商店后台或真实交易验证。

用户要求发布时，检查远程更新及本地改动后，提交并推送现有 `once512/privacy` 仓库。等待 GitHub Pages 发布，再匿名访问实际 HTTPS 页面，确认 HTTP 200、应用名称和新内容／日期。GitHub 源文件链接不替代渲染页面检查；仅推送成功也不等于部署完成。

Google Play 后台应填写 README 列出的具体政策地址；本仓库尚无网站导航首页。本轮政策更新完成后同步现有发布地址，并验证公开页面。
